# Grounds map (outdoor terrain)

The outdoor map is a 2 x 2 km Terrain3D terrain with 1 m cells. Its vertical datum is
the Black Lake surface: **y = 0 is the water line**. The lake bed goes down to
about -16 m, the castle promontory sits at 58 m and the mountain ring reaches
about 165 m. The castle interior is a separate map.

## Pipeline

The source lives in the workspace's `art/map/` folder, next to this repository:

| Path | What it is |
| --- | --- |
| `art/map/layout.json` | The design: base relief, lake, plateaus/hills/hollows, biome regions, roads, landmarks, and where gameplay content moves (`gameplay_migration`) |
| `art/map/scripts/heightfield.py` | layout -> `out/height.raw` (2048^2 float32 metres) + `stats.json` (landmark heights, road grades) |
| `art/map/scripts/control.py` | layout + heights -> `out/control.raw` (Terrain3D control words: base/overlay texture, blend) |
| `art/map/scripts/scatter.py` | layout + heights + `vegetation.json` -> `out/scatter_<variant>.bin` (float32 x, y, z, yaw, scale per instance) and `scatter_lamp.bin` (road lamps) |
| `art/map/vegetation.json` | Vegetation/rock catalogue: scatter kind -> weighted variants; per variant model, scale, leaf/wood tint, LOD distances, collider |
| `art/map/scripts/migrate_gameplay.py` | Writes spawns, castle door portal, safe zones, encounter packs, monoliths and dummies onto the terrain in `hpmmo_sim/data` (run on the server's copy; `sync-sim` brings it to the client) |
| `art/vegetation/scripts/*.py` | Blender: Poly Haven downloads (`ph_download.py`) and the tree/prop LOD builds (`build_foliage.py`, `build_props.py`) -> `art/vegetation/out/*.glb` |
| `art/map/scripts/plan_render.py` | Top-down plan and oblique review renders |
| `art/map/scripts/pack_terrain_textures.py` | Packs PBR sets into Terrain3D's 1024 px albedo+height / normal+roughness pairs |

In this repository:

| Path | What it is |
| --- | --- |
| `tools/terrain/build_grounds.gd` | Imports `height.raw` + `control.raw` into Terrain3D regions, writes the texture set, cooks vegetation (`cook_vegetation.gd`) and registers one instancer mesh per variant, copies layout/vegetation/scatter, writes `lake_depth.png` |
| `assets/terrain/vegetation/` | Cooked tree/rock scenes (LOD0-2 meshes, foliage materials) |
| `assets/terrain/grounds/` | `layout.json`, `vegetation.json`, `scatter/*.bin`, `lake_depth.png` read at runtime |
| `assets/terrain/grounds_server_assets.tres` | Empty texture/mesh list the headless server loads instead of the full set |
| `scripts/world/grounds/` | `GroundsBuilder` (builds the whole map), `CastleExterior`, `GroundsSites` (Hogsmeade, Hagrid's hut, greenhouses, boathouse, station, Quidditch pitch, stone circle, camps, crypt, spider hollow), `GroundsLake`, `GroundsScatter` (tree/boulder colliders), `GroundsHorizon`, `GroundsLayout`, `ArchKit` |
| `assets/terrain/grounds/data/*.res` | The four 1024 m regions (Git LFS) |
| `assets/terrain/grounds_assets.tres` | The 9 ground textures and the vegetation meshes, generated by the build |
| `assets/terrain/grounds_material.tres` | Shader settings, **hand-authored** (a headless build has no shader to hold them) |
| `assets/terrain/textures/` | Packed ground textures (import: VRAM compressed, high quality, normal map disabled, mipmaps) |
| `scenes/world/grounds_terrain.tscn` + `scripts/world/grounds_terrain.gd` | The terrain node (`GroundsTerrain`) |
| `tools/terrain/grounds_preview.tscn` | Walk / fly preview (F6 in the editor) |
| `scripts/test/grounds_regression.gd` | Data, painting, collision and walking checks |

Rebuild after changing the layout:

```
cd art/map
python scripts/heightfield.py layout.json out
python scripts/control.py layout.json out
python scripts/scatter.py layout.json out
cd ../../client
godot --headless --path . -s tools/terrain/build_grounds.gd -- --src ../art/map/out
godot --headless --path . res://scenes/test/grounds_regression.tscn
```

## Texture slots

The slot order is a contract between `control.py`, `build_grounds.gd` and the
regression test:

| Slot | Name | Where control.py paints it |
| --- | --- | --- |
| 0 | grass_meadow | default ground |
| 1 | cliff_rock | slopes above ~30 deg, high moor |
| 2 | forest_floor | Forbidden Forest region |
| 3 | sand_shore | lake bed and beaches |
| 4 | gravel | road shoulders, wet shoreline |
| 5 | dirt_path | road centres (the sand set tinted to packed earth) |
| 6 | cobblestone | roads on the castle plateau and in Hogsmeade, the two plazas |
| 7 | grass_lush | overlay patches on the meadow |
| 8 | moor_grass | high ground above the treeline (the meadow set, tinted) |

The auto-shader is off: every texel is painted explicitly, so what the plan
shows is what the game shows. Hand touch-ups in the Terrain3D editor are fine,
but a rebuild overwrites them; move lasting changes into `control.py` rules.

## Collision

The dedicated server simulates every player's body wherever it is, so headless
runs use `FULL_GAME` collision (the whole heightfield). A client only needs the
ground near its camera and uses `DYNAMIC_GAME` with a 96 m radius. Dynamic
collision cannot work headless; that is why the mode is chosen by display server
and not by a flag. The ground collider is on physics layer 1, like every other
walkable surface.

`GroundsTerrain.height_at(x, z)` returns the ground height (NaN outside the map
or with no grounds loaded). The old hand-built valley (`WorldBuilder`,
`OutdoorTerrain`, `CastleBuilder`, `DistantRidges`) is gone.

## Vegetation and the server

Vegetation is not stored in the regions. A client adds the instancer meshes at
runtime from `scatter/*.bin` (`GroundsTerrain._add_vegetation`; small plants
are thinned by the quality preset's `foliage_density`). The server never
renders trees but builds the same trunk/boulder colliders from the same files
(`GroundsScatter.build_colliders`), so movement agrees on both sides. Headless
Terrain3D needs saved material and assets resources (an in-memory one makes it
try to load `res://`); that is what `grounds_server_assets.tres` is for.

## Water

The Black Lake surface is y = 0. `GroundsLake.is_water_at(x, z)` reads the
bed depth; the player swims there (unmounted), the encounter director never
places mobs on water. The water shader takes colour and shore foam from
`lake_depth.png`. Below y = -30 is the kill plane (respawn at the default
spawn). Broom flight is capped at 120 m above the ground and 175 m absolute.

## Gameplay placement

Spawn points, the castle door portal, safe zones, encounter packs, monoliths
and training dummies are written by `migrate_gameplay.py` from heights of the
same heightfield; NPCs are placed on the terrain in `game_world.gd`. After a
layout change: rerun the scripts, rebuild, run `migrate_gameplay.py` on
`server/world/addons/hpmmo_sim/data`, then `dev.ps1 sync-sim` and
`dev.ps1 sync-world`.
